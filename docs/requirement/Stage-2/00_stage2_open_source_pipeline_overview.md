# Stage 2 Requirements — Open-Source-First Basketball Video Analysis Pipeline

## Purpose

This document defines **Stage 2**. Use this exact name consistently.

Stage 2 is the next major stage after the existing live game logging system. The current web app already has a command-history style UI for recording basketball events during a game. Stage 2 should reuse that existing command history as its primary input context.

The goal is to build an **open-source-assisted basketball video analysis pipeline** that uses the existing web UI command history plus game video to generate shot chart, heatmap, and halftime analytics.

## Existing context

- Frontend: React + Vite
- Deployment: Cloudflare Pages
- Existing feature: live game event logging
- Existing UI artifact: command history from the web UI

## Critical input requirement

Stage 2 must use the **existing web UI command history format** as the game log input.

This command history is not an arbitrary text file format. It is the exact history/context generated by the current live logging UI.

Example command history:

```txt
+00:41 alden layup make wes
+00:26 op ft miss
+00:24 op ft make
+00:17 op or
+00:12 op three miss
+00:07 wes three make max
+00:00 tip
```

Stage 2 must preserve this context:

- original raw command line
- order of commands
- game clock / elapsed timestamp
- period or segment if available from the UI
- player names if present
- ambiguous command patterns
- parse warnings

## Why structured intermediate files are still needed

The input remains the existing command history format. However, Stage 2 needs internal structured artifacts so that React, Python scripts, video processing tools, and AI modules can exchange results.

Use JSON internally for module-to-module exchange, but do not expose JSON as the primary user-facing input format.

User-facing flow:

```text
Existing Web UI Command History
    ↓
Import / reuse command history context
    ↓
Run Stage 2 pipeline
    ↓
View shot chart / heatmap / evaluation
```

Internal flow:

```text
command_history.txt
    ↓
parsed_timeline.json
    ↓
clip_manifest.json
    ↓
ball_hoop_detections.json
    ↓
shooter_localization.json
    ↓
court_mapped_shots.json
    ↓
shot_chart_data.json
```

### 2. basketball_analysis

Repository:

```text
https://github.com/abdullahtarek/basketball_analysis
```

Use for modular basketball video analysis structure, player detection/tracking ideas, ball acquisition logic, team assignment ideas, and tactical-view conversion concepts.

Repository:

```text
https://github.com/Purgty/Basketball-Homography
```

Use for court homography mapping, court keypoint detection concepts, mapping video coordinates to a 2D court template, and smoothing/fallback mapping strategy.

## Desired Stage 2 architecture

```text
Existing command history from web UI
    ↓
Command-history parser with context preservation
    ↓
Shot event timeline
    ↓
Clip extraction from full game video
    ↓
Open-source CV pipeline
    ├── AI-Basketball-Shot-Detection-Tracker: ball + hoop
    ├── basketball_analysis / YOLO tracking: players + shooter
    ├── Basketball-Homography: court mapping
    └── SnapFind local demo: optional search/debug helper
    ↓
Shot location / shot zone estimation
    ↓
Shot chart / heatmap / halftime report
    ↓
Existing React website display
```

## Manual fallback policy

Manual review is allowed, but only as fallback. The main Stage 2 pipeline must attempt open-source-assisted detection first.

## Definition of done

Stage 2 is acceptable when:

- existing web UI command history can be imported/reused with context
- shot events can be parsed from command history
- short video clips can be created from command-history timestamps
- ball/hoop detection runs using or adapting AI-Basketball-Shot-Detection-Tracker
- player/shooter localization uses open-source tracking concepts
- court mapping uses Basketball-Homography concepts
- SnapFind local demo path is documented as optional helper
- shot chart and heatmap are displayed in the existing website
- manual fallback is clearly distinguished from automatic/open-source-assisted results
